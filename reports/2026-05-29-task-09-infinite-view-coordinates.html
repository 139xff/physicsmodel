Task 09: Infinite View Coordinate Framing

DONE Completed: 2026-05-29T01:05:00+08:00

Scope Delivered

  • Added dynamic 2D SVG viewBox framing so large finite source and probe coordinates remain inside the rendered 2D view instead of being clipped by the old fixed 0 0 100 100 window.
  • Changed the 2D heatmap cell size and overlay sample grid to follow the current scene/probe extent, instead of always sampling near the origin.
  • Added 3D scene framing that computes a bounding sphere for all sources plus the probe, then updates OrbitControls target, camera distance, near/far clipping, grid size, and axes size.
  • Added browser smoke coverage for a point source and probe placed hundreds of meters apart, checking that the 2D viewBox contains them and the 3D camera frame expands.
  • Changed source editing to update from input events as well as change events so vector edits do not leave stale zero-vector intermediate state in the solver request path.

Scope Deferred

  • This task supports unbounded finite JavaScript numeric coordinates; literal Infinity/NaN scene coordinates remain invalid and are not sent to the solver.
  • 2D panning and zoom controls are still future work; this change auto-frames the current scene.
  • 3D direct manipulation and high-fidelity infinite-plane rendering remain outside this slice.

Known Risks And Limitations

  • The 3D camera currently auto-reframes on render/state changes, which is useful for large coordinates but may reset a user's manually orbited camera after edits.
  • The 2D auto-frame keeps the default origin frame in view, so extremely distant scenes can still make objects appear small until manual pan/zoom controls are added.
