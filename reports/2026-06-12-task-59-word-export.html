制作过程中遇到的问题与解决方法

问题 解决方法
不能依赖全局 Python、npm、pandoc 或 Word 自动化。 使用项目本地 uv 调用 Python 标准库，直接生成 DOCX 所需 XML 文件并压缩成 Office Open XML 包。
第一次内容抽检使用 Bash heredoc 写法，PowerShell 不支持 <<。 改用 PowerShell here-string 管道：@' ... '@ | .\.tools\uv\uv.exe run python -。
转换脚本最初只解析标题、段落、列表、表格和代码块，漏掉 HTML 中 div.formula 里的公式。 扩展解析器，额外捕获公式块和范围说明块，再重新生成 DOCX。
ruff 对长 XML 字符串报 E501。 对该转换脚本添加文件级 # ruff: noqa: E501，保留 Office XML 字符串的可读性，同时修正导入排序。
